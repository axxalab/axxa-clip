# HotClip v0.17.0 — Quanto mais você corta o vídeo longo, mais rápido fica

Esta versão transforma a espera da exportação repetida em um resultado local reaproveitável, e limita o «rápido» ao que dá para provar que é seguro.

- Cache limitado da renderização de base: quando o arquivo de origem, os pontos de corte, a legenda, o enquadramento, o tratamento de áudio e os parâmetros de marca são os mesmos, o vídeo de base já pronto é reaproveitado direto. A escrita do cache é atômica, a entrada corrompida se invalida sozinha, e o descarte segue o uso mais recente, ocupando no máximo 1 GB por padrão.
- Cópia direta segura por quadro-chave: o fluxo de vídeo só é copiado quando é H.264, o trecho é único e contínuo, o início cai comprovadamente em um quadro-chave e não há nenhum filtro de imagem. O áudio continua passando inteiro pela codificação AAC, pelo fade das bordas, pela redução de ruído, pela normalização de volume e pelo silenciamento das palavras de risco.
- Volta transparente: quando a detecção do quadro-chave fica incerta, as condições de codificação não batem ou a cópia direta falha, tudo volta sozinho para a codificação exata de sempre; sem codificador de hardware disponível, ainda volta para o libx264.
- Compartilhado por todas as portas de entrada: a exportação manual do aplicativo, o monitoramento de gravações / webhook, a CLI e o MCP usam o mesmo cache local.
- Visível, controlável e limpando só o que é para limpar: o diagnóstico mostra quanto o cache de renderização ocupa; depois de uma segunda confirmação, as configurações limpam apenas o vídeo de base, que dá para gerar de novo, sem apagar projeto, material de origem, modelo, cache de transcrição, credencial ou configuração.

Verificação: os 99 arquivos de teste passaram, com 1042 itens aprovados e 1 pulado pela condição de sempre; entre eles, testes de integração com FFmpeg de verdade para a cópia direta por quadro-chave em H.264, para o tratamento de áudio e para a restauração do cache.

# HotClip v0.17.0 — Faster repeat exports for long videos

This release turns repeated rendering work into a reusable local artifact, while enabling speedups only when safety can be proven.

- Bounded base-render cache: matching source, cuts, captions, reframing, audio processing and brand inputs restore an exact completed base render. Writes are atomic, corrupt entries invalidate automatically, and LRU pruning caps the cache at 1GB by default.
- Keyframe-safe smart copy: H.264 video is stream-copied only for a single continuous cut whose start is proven keyframe-aligned and whose pixels are unchanged. Audio still receives AAC encoding, edge fades, denoise, loudness normalization and sensitive-term muting.
- Transparent fallback: uncertain probes, ineligible edits or stream-copy failures return to accurate encoding; unavailable hardware encoders still fall back to libx264.
- Shared everywhere: desktop exports, folder watch / webhooks, CLI and MCP use the same local cache.
- Visible and scoped: health diagnostics show render-cache usage, and the two-step cleanup removes only reproducible base renders — never projects, source media, models, transcript cache, credentials or settings.

Verification: all 99 test files passed, with 1,042 passing tests and 1 existing conditional skip, including a real FFmpeg H.264 keyframe-copy, audio-processing and cache-restore integration test.
